## 1. P0 右侧内容溢出（截图可见）

- [x] 聊天区内容整体超出右边界：用户气泡、助手气泡、代码块都被屏幕右缘裁掉，
      代码块的「复制」角标只露出半个「复」字。
- [x] 根因候选：`ChatView` 的内层 `Column` 同时使用 `.width('100%')`、
      `.layoutWeight(1)` 和 `.constraintSize({ maxWidth: 940 })`；
      `MessageBubble` 的 `Row` 在 `ListItem` 内宽度不确定时，
      百分比 `constraintSize({ maxWidth: '82%' })` 可能按无界父宽解析而被忽略，
      气泡最终按最长代码行撑开。
- [x] 修复方向：
  - 给聊天内容列一个确定的可用宽度（`layoutWeight` + 父级 `Row` 约束），
    不要在百分比上限与 `width('100%')` 之间形成循环依赖；
  - 气泡外层用明确的 `maxWidth`（按窗口宽度计算）或
    `Row().layoutWeight(1)` + 内层 `Column` 收口，保证左右各留 20vp；
  - 代码块保持 `width('100%')`，长行在块内换行或提供块内横向滚动，
    复制按钮必须完整可见；
  - 平板横屏、竖屏、分屏三种宽度各验证一次。
- [ ] 回归：截图中的「7 条消息 …」长对话再次打开，右侧不再被裁切。
      （布局已改，待平板实机按横屏/竖屏/分屏各验一次。）

### 1.1 第二轮：气泡内部子面板仍溢出（2026-11-08 实机截图）

截图 `docs/assets/ui-overflow-2026-11-08-1.png` / `-2.png` 暴露出第一轮修复没覆盖的部分：

- [x] 现象：助手白卡右缘在 82% 处，但卡片里的「思考过程」「list_dir」灰条
      一路伸到屏幕右侧，灰条上的「展开」「完成」落在白卡外面。
- [x] 根因：助手的 `Column` 用百分比 `constraintSize({ maxWidth: '82%' })`
      收口。ArkUI 先按父级给的**未收口**宽度测量子组件，再把气泡自身裁到 82%；
      子面板的 `width('100%')` 因此按未收口宽度算，天然比气泡宽。
      这是第一轮「给父级确定宽度」没有解决的最后一层：父级确定了，气泡自己的
      百分比上限仍然是「先量后裁」。
- [x] 修复：助手气泡改为 `.width('100%')`（消息列已经是
      `layoutWeight(1)` 的确定宽度），内部所有 100% 子面板与气泡同宽；
      不再使用百分比 `maxWidth`。用户气泡内容简单（短文本 + 图片），
      保留 80% 上限。
- [ ] 回归：同样需要在横屏 / 竖屏 / 分屏下各看一次长回答
      （含思考链、工具卡、代码块、表格）。

## 2. P1 思考等级入口

现状：`AppSettings.thinkingLevel` 已存在，设置页有「思考等级」选项，
`/thinking` 可在 off → low → medium → high 间循环，请求体带
`reasoning_effort`。**但聊天界面没有入口**，必须进设置或输入斜杠命令。

- [x] 在输入框上方或顶栏模型胶囊旁增加思考等级快捷选择
      （关闭 / 低 / 中 / 高），当前会话立即生效。
- [x] 显示当前值的轻量标签，不占用大块空间；切换时写入会话覆盖值
      （`SessionMeta.thinkingOverride`），新会话回落到全局默认。
- [x] 不支持的模型/协议（如 Anthropic 原生、Gemini）隐藏或禁用该入口，
      避免发出无效参数。
- [x] 与 `/thinking` 命令保持同一份状态，设置页、顶栏、斜杠命令三处同步。

## 3. P1 思考链展示（参考 dsh-Go）

现状：`MessageBubble.reasoningPanel()` 默认折叠，流式时显示「思考中…」，
提供「展开 / 收起」；没有自动展开、自动收起，也没有耗时与摘要。

- [x] 流式生成时自动展开思考过程，让用户看到模型正在想什么。
- [x] 生成结束后自动收起为一行（如「思考了 12 秒」），点击可重新展开。
- [x] 用户手动展开后，本轮结束不强制收起（尊重手动状态）。
- [x] 折叠行显示可读摘要：首行或前 N 字，而不是只有「思考过程」。
- [x] 长思考内容独立滚动，避免把消息撑得过长。
- [x] 思考内容与正文之间的视觉层级参考 dsh-Go：弱化背景、左侧细线、
      等宽或次级字号，不抢正文。

## 4. P1 对话压缩

现状：**已有**。
- `/compact` 手动触发：保留最近 3 个用户轮次，较早内容由模型生成摘要替换
  （`ContextBudget` + `ChatApi.summarizeConversation`）。
- 发送前按预算截断较早的工具结果（`ContextBudget`），不改动已存记录。
- 顶栏显示 `上下文 5.3k / 128k (4%)`。

缺失 / 待补：

- [x] 上下文接近上限时自动压缩（阈值可配置，例如 80%），而不是只在
      用户手动 `/compact` 时压缩。
- [x] 压缩前后给出明确提示（「已把较早的 N 轮压缩为摘要」），并支持撤销。
- [x] 压缩摘要作为独立可见节点，而不是伪装成普通系统消息。
- [x] 压缩失败（模型报错 / 超时）时保留原历史，绝不丢消息。
- [x] 与思考链、工具结果一起压缩时，保留工具调用与结果的配对关系。

现状：设置页有「查看事件日志」，但每行是普通 `Text`，没有
`copyOption`，不能选中复制；没有「复制全部」、没有单条复制、
没有搜索/筛选，高度只有 220vp；崩溃栈只能导出诊断包后离线看。

- [x] 日志行支持长按选中 / `CopyOptions.LocalDevice`。
- [x] 增加「复制全部日志」按钮，复制内容仍为脱敏后的行。
- [x] 增加单条复制入口（长按菜单或行尾按钮）。
- [x] 日志查看器支持按级别（info/warn/error）和事件类型筛选。
- [x] 支持按时间或关键词搜索。
- [x] 崩溃记录可在应用内直接查看完整堆栈，并可复制；
      不要只能「导出诊断包 → 找文件」。
- [x] 日志查看器高度可调或全屏打开，不要固定 220vp。
- [x] 继续遵守：日志只存元数据，不记录提示词、消息正文、API Key、沙箱 Token。
